# sbt-mima-bom

An sbt plugin that checks **binary compatibility across an entire classpath described by a BOM**
(a Maven `dependencyManagement` pom, e.g. as generated by
[sbt-artifact-bom](https://github.com/akka/sbt-artifact-bom)).

Given a *previous* BOM (resolved from a repository, or a local file) and the *current* BOM file,
the `bomCompat` task fails the build if:

1. **An entry was dropped** from the BOM — a dependency users may rely on being present on the
   shared classpath — unless the removal is explicitly allowlisted.
2. **An entry's version changed to a binary-incompatible one**: for every entry whose version
   differs, the old and new jars are resolved and compared with
   [MiMa](https://github.com/lightbend-labs/mima) (backward compatibility, old → new).

Additions and binary-compatible upgrades are reported but never fail the check. While analyzing a
jar pair, the jars of *all* current BOM entries are used as MiMa's context classpath, so types
inherited from sibling BOM entries resolve properly.

## Usage

```scala
// project/plugins.sbt
addSbtPlugin("io.akka.sbt" % "sbt-mima-bom" % "0.1.0-SNAPSHOT")
```

```scala
// e.g. in akka-runtime, checking the shared-classpath BOM against the last release
lazy val bomCompatCheck = project
  .enablePlugins(MimaBomPlugin)
  .settings(
    bomCompatPreviousArtifact := Some("io.akka" % "akka-runtime-dependencies" % "1.5.0"),
    bomCompatCurrentFile :=
      (ThisBuild / baseDirectory).value / "artifact-bom" / "akka-runtime-dependencies" / "pom.xml")
```

Then run `bomCompat` (fails on violations) or `bomCompatReport` (returns the structured report).

## Settings

| Key | Type | Purpose |
|---|---|---|
| `bomCompatPreviousArtifact` | `Option[ModuleID]` | Coordinates of the released baseline BOM; its pom is resolved from the configured resolvers. |
| `bomCompatPreviousFile` | `Option[File]` | Local baseline pom; takes precedence over the artifact (useful for comparing git revisions). |
| `bomCompatCurrentFile` | `File` | The current BOM pom (default: `baseDirectory / "pom.xml"`). |
| `bomCompatAllowedRemovals` | `Set[String]` | `"org:name"` entries that may legitimately disappear. |
| `bomCompatIgnoredModules` | `Set[String]` | `"org:name"` entries to skip in the MiMa analysis (still presence-checked). |
| `bomCompatProblemFilters` | `Seq[ProblemFilter]` | MiMa filters applied to every module. |
| `bomCompatModuleProblemFilters` | `Map[String, Seq[ProblemFilter]]` | MiMa filters per `"org:name"` module. |
| `bomCompatExcludeAnnotations` | `Seq[String]` | Annotations (FQCN) whose carriers are exempt, e.g. `akka.annotation.ApiMayChange`. |

Example filter — suppress findings in a library's shaded internals:

```scala
import com.typesafe.tools.mima.core._

bomCompatModuleProblemFilters := Map(
  "io.netty:netty-common" -> Seq(
    ProblemFilters.exclude[Problem]("io.netty.util.internal.shaded.*")))
```

## Notes and limitations

- Entries with a classifier (e.g. native artifacts) or a non-`jar` type are skipped for MiMa
  analysis, with a warning.
- Maven property interpolation (`${...}`, including `project.version`) is supported, but parent
  pom inheritance is not: the BOM must be self-contained.
- Entries whose jar cannot be resolved are skipped with a warning rather than failing the build.
- The first run resolves every jar in the BOM; subsequent runs hit the local cache.

## Development

`sbt scripted` runs the integration tests (requires network access to Maven Central).
